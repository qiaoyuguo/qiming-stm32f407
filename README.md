# qiming-stm32f407

STM32F407 embedded firmware workspace, built with the **STM32 HAL** library and generated by **STM32CubeMX**. The project is developed, compiled and debugged entirely from VS Code (no STM32CubeIDE required).

## System Overview

| Item | Value |
| --- | --- |
| MCU | STM32F407ZGTx (Cortex‑M4F, LQFP144) |
| System clock | 168 MHz (HSE 25 MHz, PLL) |
| Firmware library | STM32F4xx HAL (generated by STM32CubeMX) |
| Build system | CMake with Unix Makefiles generator |
| Debug probe | DAP‑Link (CMSIS‑DAP / SWD) |
| IDE | VS Code (no STM32CubeIDE) |

## Software Dependencies

- **ARM GNU Toolchain** (`arm-none-eabi-gcc`)
  - Location: `/Applications/ArmGNUToolchain/15.2.rel1/arm-none-eabi/bin` (in `PATH`)
  - Cortex‑M4, hard‑float (`-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard`)
- **CMake** ≥ 3.22 and **make** (`/usr/bin/make`)
  - Generator is `Unix Makefiles` (ninja is not installed)
- **OpenOCD** — `/opt/homebrew/bin/openocd`
  - Scripts: `/opt/homebrew/share/openocd/scripts`
  - Interface: `interface/cmsis-dap.cfg`, Target: `target/stm32f4x.cfg`
- **VS Code extensions**
  - `marus25.cortex-debug` — debugging
  - C/C++ (ms‑vscode.cpptools) — IntelliSense / build tasks
- **STM32CubeMX** — used to (re)generate the HAL project skeleton (optional, not needed for building)

## Build & Debug Configuration

Build presets are defined in `CMakePresets.json`:

- **Debug** — `-O0 -g3` (default, produces `build/Debug/001-FlowLight.elf`)
- **Release** — `-Os -g0` (produces `build/Release/001-FlowLight.elf`)

VS Code tasks (in `001-FlowLight/.vscode/tasks.json`):

- **Compile Debug** (default build task): `cmake --preset Debug && cmake --build --preset Debug`
- **Compile Release**: `cmake --preset Release && cmake --build --preset Release`
- **Clean**: `rm -rf build`

Debugging is handled by `cortex-debug` (`001-FlowLight/.vscode/launch.json`), which launches OpenOCD against the DAP‑Link probe over SWD, flashes the firmware and halts at `main`.

> **Note:** OpenOCD must run **outside** the VS Code terminal sandbox to access the USB probe (the sandbox blocks USB access → "unable to open CMSIS-DAP device"). VS Code F5 debug sessions are not sandboxed, so `cortex-debug` works normally.
