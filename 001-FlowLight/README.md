# 001-FlowLight (流水灯)

A simple **flowing light** example for the STM32F407ZGTx. Three on-board LEDs blink in sequence, producing a "running light" effect. It is the first sample project in this workspace and serves as a minimal HAL-based template (clock + GPIO + main loop).

## Hardware Requirements

| Resource | Pin |
| --- | --- |
| LED0 | PE3 (GPIOE pin 3) |
| LED1 | PE4 (GPIOE pin 4) |
| LED2 | PG9 (GPIOG pin 9) |
| Debug probe | DAP‑Link via SWD (CMSIS‑DAP) |

All three LEDs are configured as push‑pull outputs, low speed, no pull-up/pull-down.

## Features

- System clock configured to **168 MHz** (HSE 25 MHz → PLL: M=25, N=336, P=2)
- Three LEDs toggle sequentially with a **500 ms** delay between each
- Repeats forever once the device starts
- Built and debugged directly from VS Code (CMake + cortex-debug)

## How It Works

The core logic lives in `Core/Src/main.c`:

1. **Startup / initialization**
   - `HAL_Init()` — resets peripherals, initializes the Flash interface and SysTick.
   - `SystemClock_Config()` — drives the system to 168 MHz using the PLL.
   - `MX_GPIO_Init()` — configures PE3/PE4 and PG9 as push-pull outputs, all initially set high (LEDs off).

2. **Main loop** — the flowing effect:
   ```c
   while (1)
   {
     for (int i = 0; i < 3; i++)
     {
       HAL_GPIO_TogglePin(gpios[i], pins[i]);
       HAL_Delay(500);
       HAL_GPIO_TogglePin(gpios[i], pins[i]);
     }
   }
   ```
   For each LED in turn (`gpios`/`pins` arrays hold the port/pin pairs for LED0–LED2):
   - toggle the LED **on**,
   - wait 500 ms,
   - toggle it **off** again.

   Because the LEDs are processed sequentially inside the loop, only one LED is lit at a time — the light visually "flows" from LED0 → LED1 → LED2 and then restarts.

## Implementation Notes

- **Generated code** — The project skeleton (startup file, linker script, HAL drivers, `gpio.c`, clock config) is generated by **STM32CubeMX** and kept under the `USER CODE` sections, so it can be safely regenerated without losing custom logic.
- **HAL GPIO API** — `HAL_GPIO_TogglePin()` flips the pin state; `HAL_Delay()` provides a blocking 500 ms delay based on SysTick.
- **Active-low LEDs** — pins are driven to logic high on init (off); the effect is produced purely by toggling.

## Build & Flash

Build (Debug, default):

```sh
cmake --preset Debug && cmake --build --preset Debug
```

The resulting firmware is at `build/Debug/001-FlowLight.elf`.

To flash and run, press **F5** in VS Code (`cortex-debug` + OpenOCD) — it builds, flashes via the DAP‑Link probe and halts at `main`. You can also flash manually:

```sh
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
        -c "program build/Debug/001-FlowLight.elf verify reset exit"
```
