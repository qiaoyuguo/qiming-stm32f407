# 002-KeyScanByDelay (按键扫描)

A **key-scan** example for the STM32F407ZGTx that reads four on-board push buttons using a simple **blocking (delay-based) scan** with software debouncing, and drives the LEDs and buzzer in response. It demonstrates digital input handling (`GPIO_MODE_INPUT` with pull-up) and how to debounce a mechanical switch in the HAL library.

## Hardware Requirements

| Resource | Pin | Role |
| --- | --- | --- |
| KEY0 (UP) | PF9 (GPIOF pin 9) | Input, pull-up, active low |
| KEY1 (LEFT) | PF8 (GPIOF pin 8) | Input, pull-up, active low |
| KEY2 (DOWN) | PF7 (GPIOF pin 7) | Input, pull-up, active low |
| KEY3 (RIGHT) | PF6 (GPIOF pin 6) | Input, pull-up, active low |
| LED0 | PE3 (GPIOE pin 3) | Push-pull output |
| LED1 | PE4 (GPIOE pin 4) | Push-pull output |
| LED2 | PG9 (GPIOG pin 9) | Push-pull output |
| BEEP (buzzer) | PG7 (GPIOG pin 7) | Push-pull output |
| Debug probe | DAP‑Link via SWD (CMSIS‑DAP) | — |

All four keys are configured as inputs with internal **pull-up** resistors and are **active low** — a key is "pressed" when the pin reads `GPIO_PIN_RESET`.

## Features

- System clock configured to **168 MHz** (HSE 25 MHz → PLL: M=25, N=336, P=2)
- Reads four push buttons with a **delay-based scan** (`HAL_Delay` polling loop)
- **Software debouncing** via a 10 ms delay and a second read to confirm the press
- Each key drives a different action:
  - **KEY_UP** → LED0 **on**
  - **KEY_DOWN** → LED0 **off**
  - **KEY_LEFT** → LED1 **toggle**
  - **KEY_RIGHT** → LED2 **toggle** + a short buzzer beep
- Built and debugged directly from VS Code (CMake + cortex-debug)

## How It Works

The core logic lives in `Core/Src/main.c`.

1. **Startup / initialization**
   - `HAL_Init()` — resets peripherals, initializes the Flash interface and SysTick.
   - `SystemClock_Config()` — drives the system to 168 MHz using the PLL.
   - `MX_GPIO_Init()` — configures KEY0–KEY3 as pull-up inputs and LED0–LED2 / BEEP as push-pull outputs.

2. **Key scanning (`KeyScan`)** — a blocking, delay-based scan:
   ```c
   uint8_t KeyScan(void)
   {
     if (KEY_UP == GPIO_PIN_RESET)
     {
       HAL_Delay(10);                 // Debounce delay
       if (KEY_UP == GPIO_PIN_RESET)  // Confirm the press
       {
         return KEY_UP_PRESSED;
       }
     }
     // ... same pattern for KEY_DOWN / KEY_LEFT / KEY_RIGHT ...
     return KEY_NONE;
   }
   ```
   Each key is checked in sequence. When a pin is read low, the code waits **10 ms** and reads it again — if it is still low, the key is considered pressed and the corresponding state is returned. This double-read approach filters out contact bounce.

3. **Main loop** — reacts to the scanned key state:
   ```c
   while (1)
   {
     KeyStateTypeDef keyState = KeyScan();
     switch (keyState)
     {
       case KEY_UP_PRESSED:     HAL_GPIO_WritePin(LED0, GPIO_PIN_SET); break;
       case KEY_DOWN_PRESSED:   HAL_GPIO_WritePin(LED0, GPIO_PIN_RESET); break;
       case KEY_LEFT_PRESSED:   HAL_GPIO_TogglePin(LED1, ...); break;
       case KEY_RIGHT_PRESSED:  HAL_GPIO_TogglePin(LED2, ...);
                                /* short beep */ break;
       default: break;
     }
   }
   ```
   The loop continuously scans the buttons and dispatches each press to the matching LED / buzzer action.

## Implementation Notes

- **Active-low keys with pull-up** — the buttons connect the pin to ground when pressed, so a press reads `GPIO_PIN_RESET`.
- **Delay-based debounce** — a fixed 10 ms `HAL_Delay` plus a confirm re-read. This is simple but **blocks** the CPU; a timer/EXTI-based scan would be non-blocking.
- **Blocking scan** — `KeyScan` is called every loop iteration, so the LEDs and buzzer are driven from within the same loop.
- **Generated code** — The project skeleton (startup file, linker script, HAL drivers, `gpio.c`, clock config) is generated by **STM32CubeMX** and kept under the `USER CODE` sections, so it can be safely regenerated without losing custom logic.

## Build & Flash

Build (Debug, default):

```sh
cmake --preset Debug && cmake --build --preset Debug
```

The resulting firmware is at `build/Debug/002-KeyScanByDelay.elf`.

To flash and run, press **F5** in VS Code (`cortex-debug` + OpenOCD) — it builds, flashes via the DAP‑Link probe and halts at `main`. You can also flash manually:

```sh
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
        -c "program build/Debug/002-KeyScanByDelay.elf verify reset exit"
```
